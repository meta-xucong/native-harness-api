# 真实增量事件实施补充

用户后续明确以“及时、如实反映 WorkBuddy 内容与任务状态”为验收重点，不要求
与原始模型 API 完全相同。因此扩展历史首版非流式边界，采用原生事件协议，
不再将 buffered-final 当作实时能力。原唯一 Bridge 账本、可信单用户、冻结路由、
审批不代答、未知不重执行及未知用量不造假原则保持。

Node 依据固定官方合同生成已绑定请求的文本快照与原生状态；Bridge 负责有界持久
事件日志与唯一顺序；Facade 负责身份、摘要、终态验证；Sub2 负责真实鉴权和逐事件
SSE交付。快照可替换，idle不表示完整结束。事件详情、恢复与故障合同见
[代码合同](../code/docs/NATIVE_EVENT_STREAM.md)。

必须验证：终态前可见内容、快照缩短/更正、ACK前消息隔离、断线后同任务游标恢复、
重复上报去重、审批/unknown及时反映、终态真实、慢客户端有界与错误非成功。
离线协议/真实HTTP/临时数据库测试不等于真实WorkBuddy账号已验证。
