# 通用多 Harness 实施与验收计划

v0.3 附录。以下全部是**待实施/待验证测试要求**，不是本轮PASS计数。本轮只改蓝图，不运行第三方程序、不登录、不推理、不部署。

## A. 切片顺序与变更范围

| 切片 | 允许实现内容（后续获准阶段） | 必须保持 |
|---|---|---|
| D1a 配置与身份 | versioned Adapter/profile/model注册；显式旧WorkBuddy映射；跨仓冻结字段/迁移方案 | 旧digest不改、旧结果不重跑、默认关闭 |
| D1b Core与双Adapter fixture | 提取协议无关owned lifecycle/事件关联挂钩；两个不同协议替身共享一个Node槽 | 只有Bridge派发、不增加队列、未知阻塞共享资源 |
| D1c WorkBuddy回归 | 以原固定SFE及模型/profile约束通过同一Core；只替内部接缝 | 当前登录/隐私/Windows/流/模型/usage边界不降低 |
| D2 Codex Adapter | 官方App Server固定版本独立登录/模型/turn与事件协议 | 不读取或转存token，不以文本自报模型；approval不代答 |
| D3 豆包可行性 | 官方资产和参数核验，先无账号只读/初始化，再显式用户本地试用 | internal包不默认升级为稳定产品；无法核证就保持禁用 |
| D4 其他 | 千问办公专项；Qwen Code/CodeBuddy独立Adapter | 不以名称近似替换用户指定软件 |
| D5 运营 | 新渠道类型、隔离及明确计费策略、真实部署预检 | 不影响现有404token/image/video路由、不自动上线 |

实现阶段同步 code/、Bridge、Sub2API具体合同与迁移；本蓝图不是可导入配置。每一切片先设计/独审、最小源码、离线与平台测试、精确提交CI、打包实物核验；真实账号留给用户授权试用，不要求由开发方代登录才能写完代码。

## B. 通用契约反例

| ID | 场景 | 必须结果 |
|---|---|---|
| MH01 | WorkBuddy/Codex模型同名 | 绑定和厂商/profile独立，无隐式合并/切换 |
| MH02 | 32个别名跨两个Harness同时提交 | 整个Node单槽；不同时出现两个已授权原生任务。单任务可有受控子进程/子Agent，不能按进程数判断槽占用；队列仅Bridge既有有界机制 |
| MH03 | A开始后电脑掉线，B可用 | A保持原操作/unknown；B不接管A；共享域未停确认不放槽 |
| MH04 | 同键切Adapter/模型/地区/账号/能力/版本 | 原冻结任务只读恢复或冲突，不能新执行 |
| MH05 | 旧v1任务→v2升级→删除旧绑定 | 旧digest/owner/key仍可找原记录；记录缺失不自动补建执行 |
| MH06 | v2任务后代码回滚 | 不回滚账本；旧程序不理解即停准入/隔离，不重新生成 |
| MH07 | ACK前事件、旧thread、其他前台turn、subagent | 不串根回答；按各协议真实关联，缺归属保守拒绝 |
| MH08 | delta、全量替换、缩短、空快照、emoji跨帧 | 原生快照正确；标准append重写明确错误且无成功DONE |
| MH09 | idle/Stop hook/exit0但任务无完成证据 | 不伪成功；本地活性与业务终态独立 |
| MH10 | 原生cancel ACK但子进程或远端任务仍活跃 | 取消请求≠停止；本地owned收尾不能证明远端回滚 |
| MH11 | 用户断流/慢socket/重连/游标超前/日志过期 | 只观察原任务；超时/过期明确错误，启动次数不增 |
| MH12 | 高频长答/状态密集/磁盘满/超限 | 合并仅未发连续快照、状态屏障保序、最终答案完整；超限不截断成功 |
| MH13 | 模型选择成功但回读错、全局设置竞争、原生auto | 拒固定模型成功；auto仅显式别名，不伪造型号 |
| MH14 | 需原生审批、重复/迟到/跨任务审批 | 未实现UI按声明拒绝；实现后具体动作绑定且一次性，绝不自动批准 |
| MH15 | SDK请求不支持角色、历史、tools、模态 | 新执行前拒绝；不默默拼接或吞字段 |
| MH16 | 账号切换/同产品跨地区/profile目录替换 | 身份代际/路径/锁校验；不覆盖旧profile和旧恢复身份 |
| MH17 | Adapter加载任意URL/包/命令 | 静态白名单拒绝；升级以独立审计包及版本证明推进 |
| MH18 | 短命/孙进程/宿主先退出/启动后控制器崩溃 | OS进程树证据正确；迟到spawn与unknown保持围栏，不因PID不见释放 |
| MH19 | usage重复/缺失/合法0/多子调用/不同计量单位 | 去重、unknown/partial明示；不把上下文或累计成本重复相加，不自动计费 |
| MH20 | 不同用户/Key/租户相同幂等键 | 按真实认证范围隔离，未授权回放拒绝；更换Key不自动建立跨Key恢复权 |
| MH21 | Adapter/schema版本未知，heartbeat伪造能力 | 不准入新执行；声明不能替代版本、绑定和服务端授权 |
| MH22 | 原有WorkBuddy和普通404token渠道 | 既有功能/计费/重试不受通用扩展影响；无新vendor烟测被意外自动触发 |

## C. 每个 Adapter 独立验收表

必须列出（未知填NOT_RUN/UNSUPPORTED，不能空白）：
1. 官方入口和来源、版本/OS/地区；精确机器协议、许可证和使用范围调查。
2. 无账号初始化的真实结果、可能隐式IO及副作用；没有可靠无副作用入口时不假称安全探针。
3. 用户自行登录、profile存储保护、默认浏览器与认证持久化说明；清楚是否可复用GUI状态。
4. 模型目录、选择scope、逐任务回读、隐式fallback控制及失败反例。
5. session/thread/turn/item归属、流模式、拒答/错误/取消/终态的完整映射。
6. 只读恢复支持与局限；不支持时unknown处置和管理员说明，不提供删journal解锁捷径。
7. 真实owned生命周期、资源锁、外部工具范围、审批和无权限场景。
8. 边界测试、可信本机账号模型试用、三仓真实socket与数据库测试分别记录。
9. 启用能力与未启用能力清单；代码ready不等于账号/生产ready。

## D. 发布与证据

- 四层验收分别标记：DESIGN_REVIEWED / CODE_FIXTURE_VERIFIED / NATIVE_ENTRY_VERIFIED / ACCOUNT_MODEL_VERIFIED；生产与收费另设独立门，不用一个“全绿”覆盖。
- 本轮蓝图审计检查职责、身份、迁移、资源隔离、协议诚实性和来源强度。审计报告记录精确文件hash、问题与关闭状态，只批准下一阶段设计工作。
- 后续测试报告保存三仓commit、Adapter与原生hash、配置摘要、实际命令结果、未跑项目和推理费用/部署状态。
- 下载包按所选Adapter列明支持矩阵和用户操作，不把WorkBuddy已测记到Codex/豆包；服务器和客户端源版本配对。
- 更新PR正文与导航时准确指出新设计而非多Harness实现。仅文档commit不得意外触发厂商运行workflow。
- 用户要求及时进度报告：完成一个实质切片/发现阻断时说明已做、现在做、剩余；没有新进展不编造测试或假称在跑。
