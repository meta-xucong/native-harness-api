# Bounded ACP model-selection compatibility

This changes only the experimental ACP client's selection readback. It does not enable the synthetic-only network channel, establish actual WorkBuddy login, or attest the provider-executed model.

The fixed official WorkBuddy 5.9.3.42398134 bundle returns `modelId` from `session/set_model`, then can publish a full `config_option_update`. That ACK is not state readback. The client sends one setter and requires its successful response plus a fresh native state observation under the existing absolute deadline. No getter, second setter, retry, process or mode change is introduced. A narrow nonblocking selection lock prevents concurrent setters without holding the lifecycle lock; closing remains able to interrupt the wait.

The initial catalogue must contain the target with valid unique identifiers. Config selectors must have an unambiguous model category, nonempty unique id, select type, string current value, and valid unique option values. Config setter responses and config notifications carry full snapshots, not patches. Missing/null/empty/removed/ambiguous model evidence fails closed. Contradictory `modelId` or `currentModelId` ACK fields fail even when other state matches.

Legacy state may upgrade once to the exact observed config selector id, never downgrade to cached legacy evidence. Pre-send queued controls are drained and cannot count as fresh selection readback. A well-formed old-value notification before the ACK may be an asynchronous initial snapshot; it does not confirm selection. Waiting for newer matching evidence uses only remaining original time. After ACK, fresh nonmatching state is rejected. Already observed deletion or unsafe permission state cannot be repaired by a later matching update.

Unsafe mode notifications are sticky during session-creation replay, selection and idle as well as prompt. Default approval behavior and global stop/owned-process supervision remain unchanged. EOF, timeout and protocol uncertainty do not retry or send a prompt.

Limitations: an observation received after send is not causally tagged to that setter by ACP. Draining the reader queue is not an atomic barrier against updates still in flight. Continued controls are checked, but this is configured-session evidence, not actual response-model provenance, task completion or execution-liveness proof.

Sources: https://agentclientprotocol.com/protocol/v1/session-config-options and https://www.codebuddy.cn/docs/cli/acp . Fixed bundle SHA256 `c57a02ee3f2ef813004262cd003774a6e71bd2a6f5005481359301b407977ea5`; decoded character offsets ~2892833 (setter ACK/deferred config event), ~3015343 (full config notification), ~3018600–3019500 (subscription and asynchronous initial push). Vendor source is not copied into this repository. Offline fixtures do not establish a successful real WorkBuddy session.


Present unsafe initial session modes are sticky before pending controls replay; absent initial mode is not newly rejected at creation, but must satisfy existing selection/prompt admission. The known native `model_update` notification is accepted only as a complete `availableModels`/`currentModelId` snapshot with unique nonempty `modelId` entries and current/target membership. Missing, malformed or contradictory snapshots fault. After config-source upgrade, matching legacy snapshots do not supply fresh config evidence, and contradictory snapshots fault. No value is assigned to reported/provider model fields.

Fixed bundle writer evidence: character ~2821145 sends `model_update` from `getModelsInfo`; ~2786474 maps catalogue entries using `modelId`. The embedded schema's `id` spelling is not silently accepted as an alias. The writer is guarded by `isWebUiClient`; supporting this observed shape does not imply ordinary stdio sessions always emit it. `current_model_update` remains the existing narrow compatibility shape, not a substitute for validating the full known native notification.

Model-bearing config snapshots are validated and their selector identity pinned immediately when observed, including initial state, idle and preselection, rather than only inspecting the last cached value at selection. A bad/deleted source cannot be repaired by later valid snapshots. Legacy `current_model_update` also requires a nonempty string belonging to the existing trusted catalogue. Well-formed old dual-source values before the setter ACK may await convergence, but clear pending confirmation and cannot certify a config source; after ACK a mismatch faults. Invalid types, source loss and unsafe modes are never delayed or repaired.
