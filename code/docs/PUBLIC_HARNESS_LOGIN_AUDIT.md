## 旧回归为什么漏检

旧模拟对端要求先接收 URL accept 才返回登录结果；UI 默认立即回答 yes。
Windows 自写对端只走直接成功，profile/environment 使用 stub。
该组合没有覆盖官方独立完成浏览器交互、报错后继续后台提交的真实控制流程。

新增对端使用源码核对后的合成时序；Windows 用例使用实际 profile 创建、ACL、锁、
环境构造、管道分帧和 Job，只有官方网络/认证及 host-node 校验数据使用合成替身。
另用旧基线动态加载同样的新协议测试，两个核心用例确实失败；不只证明新实现自洽。

## 独立审查与结果边界

协议审查与运行时审查由分别的只读审计者完成，范围监控另行复核。
复核发现并修正了不可达的 login_rejected 摘要分支，CLI测试改用实际新终态。
定向共 78 项（沙箱内 75 通过、3 项条件跳过）；完整回归共 1035 项，1029 通过、6 跳过。
全量首次受执行沙箱的回环 socket、硬链接和句柄限制失败；在获准的普通本机执行环境中
运行同一代码通过，未改变系统安全设置。offline_demo、compileall 与 diff 检查通过。
包验收的最终命令、源码版本及 ZIP 摘要保存在交付环境的 LOCAL_ACCEPTANCE 报告中。

本次解决的是可复现的本地兼容缺口。官方服务器/账号/Product 提交持续失败仍可能导致
unknown；厂商统一抹掉的 `-32603` 原始异常无法从其公共回复恢复。真实账号、模型与服务链
仍待独立实测；不承诺模拟消除了所有真实服务故障。

## 标准代理环境兼容复核

独立 profile 环境遗漏了父进程标准代理变量。固定 beta16 的 managed-auth 请求经过
`lib/internal/http.js`，该消费者依据传入环境构造 `EnvHttpProxyAgent`，不走 CLI 中另一路
Windows 系统代理探测。最小修复只保留父进程四类标准代理键（含大小写），按实际环境项
复制以避免 Windows 大小写不敏感查找产生重复键；认证目录、任意 Node 选项和 TLS 关闭
开关仍不继承，不在诊断、日志或报告中输出代理值。

新增环境用例在旧实现失败；另使用未修改的官方 HTTP transport 与本机合成 origin/proxy，
验证无变量直连、HTTP_PROXY/http_proxy/ALL_PROXY 走代理及 NO_PROXY 绕过。
官方 managed-auth factory 的个人账号及空 type 合成场景均完成登录、保存与重新读取，
全部 HTTP/浏览器交互由注入替身提供，外部网络和子进程入口被禁止。
这些证据确认环境缺口与组件基本可运行，不能将未知账号的 `-32603` 直接归因为代理。

该修复全量离线回归共 1036 项，1030 通过、6 跳过；offline_demo、compileall 与 diff
检查通过。生产变更经独立只读审查，无阻断发现；范围复核为 NO_VIOLATION_FOUND。
