# Native Harness API：开发蓝图 v0.1

日期：2026-11-07。性质：拟实施设计，不是现有能力说明。本文中的 MUST 表示必须满足；未核实的外部能力均通过阶段门禁处理。

## 1. 产品定义

让用户以 Sub2API 地址、用户 API Key 和一个原生 Harness 模型别名提交任务。真正的模型调用、工具执行、原生上下文管理和审批均发生在本地官方 Harness；VPS 只承担入站 API、任务持久化和结果交付。

用户买到的是“原生 Agent 执行服务”，不是与裸模型完全等价的推理 API。标准 API 外形不保证 seed、采样参数、逐 token 流、客户端函数调用、完整角色层级或厂商 token 计费语义全部兼容。

### 1.1 不可改变的约束

| ID | 约束 |
| --- | --- |
| INV-01 | 模型请求必须由本地官方 Harness 发出；Facade/Bridge 不实现厂商模型客户端。 |
| INV-02 | 厂商凭证留在本地原生运行环境；不得抽取、上传或改造成上游 Key。 |
| INV-03 | 本地节点只主动通过 HTTPS 与 VPS 通信；不开放 PC 公网入口、不使用 SSH 反向隧道。开发 loopback HTTP 例外仅限本机测试。 |
| INV-04 | 每个任务只有一个 VPS 执行账本权威；Facade 不再建第二套派发队列，PC journal 不是派发权威。 |
| INV-05 | 一旦已授权或可能开始执行，只能恢复同任务；断线、超时、租约过期均不授权重新生成。 |
| INV-06 | 用户 Key、Facade 服务 Key、Bridge Source Key、Node Key 与厂商登录态职责分离。 |
| INV-07 | 租户身份来自 Sub2API 已认证上下文；请求体 user、session_id 或自填请求头不构成可信身份。 |
| INV-08 | 只有原生完成证据和持久化结果一致时才成功；空输出、退出码为零、界面不再变化均不能单独证明成功。 |
| INV-09 | 不伪造流式、token 用量、模型身份、工具结果或已通过的验收。 |
| INV-10 | 首版单节点、单执行槽、每请求新会话；保留多槽字段但不提前实现分布式调度。 |
| INV-11 | 不以 API 兼容为由整体禁用原生工具，也不以原生能力为由默认全面授权。 |
| INV-12 | 本次仅蓝图；后续实现独立 PR、默认关闭，未另获授权不合并、不部署、不进行付费真实调用。 |

“禁止云端回退”覆盖本地离线、忙碌、审批超时和原生失败，不能借 Render Bridge 原有生图 fallback 策略为本产品增加厂商直连。请求重放原结果不是新推理。

## 2. 最小部署架构

```text
Client
  | Sub2API user key
  v
Sub2API [现有系统]
  | 服务 Key + 可信租户 + 稳定请求标识
  v
Harness API Facade [新仓库，VPS]
  | Bridge Source API；只 submit/get/cancel/read-result
  v
Render Bridge [现有代码复用，VPS 独立实例]
  | 唯一任务账本 + 私有结果存储；dispatch_mode=node_pull
  ^
  | PC 主动领取/认领/启动握手/回传/恢复
  v
Local Node Agent [Windows]
  | durable local journal；单槽；Adapter
  v
Local official Harness -> 该软件自己的原生模型通道
```

Facade 和 Bridge 可在同一 VPS 的不同进程运行，但不能共享内部数据库连接或通过文件旁路任务状态。二者仍通过版本化 HTTP 合同通信。Sub2API 可以同 VPS 或另一台 VPS，均不影响本地执行边界。

优先为本项目启动独立 Bridge 实例和独立数据目录，固定复用版本，不占用现有 Alchemy 渲染任务槽、不读取原有生产账本。复用的是代码和合同能力，不是无审核混用已有生产实例。新任务类型需要在 Bridge 原仓库增加兼容扩展，不把旧图片字段塞入文本。

### 2.1 职责和禁止事项

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| Sub2API | 用户/Key、入口限流、模型别名路由、可信调用归属、请求身份、最终计费 | 运行原生 Harness、处理厂商登录态、执行不明后重新切账号 |
| Facade | 接口鉴权、受支持字段转换、提交与观察同任务、标准响应 | 第二套用户钱包、任务派发调度、厂商 SDK/云端推理 |
| Bridge | 唯一任务/许可/终态/结果账本、节点准入、同任务恢复 | 改写用户原始意图、运行 Harness、业务计费 |
| Node Agent | 原生会话与槽绑定、局部持久记录、上传与重连、进程观察 | 持有用户 Key、修改远端任务身份、失联后自建新任务 |
| Adapter | 启动/观察/取消/协调原生会话，映射真实事件 | 读取厂商 token 后自己实现网络模型请求、绕过原生审批 |

Facade 不再持久化可独立派发的任务表。其请求映射和最终响应所需数据由 Bridge 文本任务扩展保存。Sub2API 的业务计费记录属于不同职责，不是第二个执行调度权威。

## 3. 首版范围与对外开放边界

### 3.1 第一条闭环

一个可信测试用户 -> Sub2API 用户 Key -> `POST /v1/chat/completions` -> Facade -> Bridge -> Windows 单槽 -> 一个原生 Harness -> 最终文本 -> 原路标准 JSON 返回。

先 FakeHarness，再选择已经证实合法可用的官方 CLI/SDK 入口完成真实闭环。若用户优先 WorkBuddy，而其本地入口未获证实，WorkBuddy 分支保持 blocked；不得换成其他 Harness 后声称 WorkBuddy 已完成。

首版只接受文本消息、一次一个结果、非流式、每请求独立会话。没有长期用户会话、没有公网文件下载、没有用户自定义命令/工作路径、没有远端客户端执行的 function calling。运行审批可以依赖本地操作者；进入审批等待必须可观察，不能无限卡住 API。

### 3.2 明确不做

不重做 Sub2API 钱包、用户系统和所有协议；不支持所有厂商；不同时堆叠 HAPI/Hatchet/Bridge 多套调度；不建设通用远程桌面 Agent；不实现账号共享规避、限流绕过、自动抢占订阅；不自动登录厂商；不做现有生产数据迁移。

“先不收费”不等于无需认证、隔离或厂商授权。真实 PoC 仍必须使用获准账号和专用测试工作区。

## 4. 原生 Adapter 合同

接口是本项目拟定义的逻辑职责，不是声称所有 SDK 具有相同函数名：

```text
capabilities() -> 已验证的能力和版本
prepare(task, profile) -> 隔离工作区与新原生会话
start(grant, session) -> 一次启动/提交
observe(run) -> 原生状态、可公开输出、审批、终态
cancel(run) -> 请求取消；返回是否已确认停止
reconcile(run, journal) -> 恢复观察既有会话/进程/结果
```

原生 continue/resume 仅用于明确已存在会话的观察或受控续接，不能自动“再发一次 prompt”。恢复 API 本身会启动新一轮推理的，不能作为无副作用的 reconcile 使用。

Profile 至少记录 `profile_id/profile_revision/harness_kind/harness_version/adapter_version/allowed_principal/workspace_policy/approval_policy/capabilities`。首次接收任务冻结版本与 profile；之后管理员修改别名或默认模型不能改变旧任务的回放身份。

| Harness | 选型 | 当前证据边界 |
| --- | --- | --- |
| Codex | 官方 CLI/SDK 或现有 Bridge 原生实现中的可复用部分 | 原生文本模式、固定版本、审批和 Windows 行为必须真实验收；不能把生图适配当成文本完成证明 |
| Claude Code | 官方 Agent SDK 驱动本地 CLI | SDK 与原生程序/服务授权分开；不整仓搬用旧 wrapper 的环境与认证管理 |
| WorkBuddy | 已研究的本地 ACP/sidecar Adapter，附条件 | 不把非公开控制入口当官方稳定 API；授权、版本、终态和隔离未过门禁不得上线 |
| 豆包 | 保留 Adapter 占位设计 | 没有已核实完整实现，不发布可调用别名，不以 GUI 静止推断完成 |

允许保留原生工具，但工具权限由服务器端受信 profile、原生审批和 OS 隔离共同控制。用户 prompt 可以描述任务，不能直接选择可执行文件、shell 参数、环境变量、插件目录或批准策略。调用 CLI 使用参数数组/stdin，不把 prompt 拼成 shell 命令。

## 5. 一次请求的生命周期

1. Sub2API 完成用户认证和当前访问权限检查，移除客户端伪造的内部请求头，构建可信租户和稳定请求标识。新执行的额度/容量预留只能作用于新操作，不得因余额或新任务限额耗尽阻断已获授权的结果回放；必要的防滥用读取限流可以独立存在。
2. Facade 验证服务 Key、可信归属及请求结构，先按操作身份查找旧任务；同键回放使用原冻结 profile，不受当前节点在线与否或新任务开关影响。仅新操作才验证已启用能力并转换支持字段，不支持的语义在新任务接收前返回错误。
3. Bridge 在一个事务内完成幂等查找/创建、准入和容量预留，持久化后才确认 ACCEPTED。存在旧任务时优先回放；Facade 的健康预检只是提示，不能替代这次原子准入。
4. PC 出站拉取任务；offer 只读，claim 原子化；所有 profile 共用该节点的一个槽，不是每个别名单独一个并发。
5. VPS 先持久记录 START_GRANTED 和 execution_possible，再返回启动许可；Node 在实际 spawn 前持久记录一次性 launch_intent。任务从发许可起即视为“可能已执行”，Node 只能消费该许可一次。
6. Adapter 创建独立原生会话，在获准工作区执行。原生程序自己访问模型；Bridge 不参与模型认证。
7. Node 持久保存输出和原生终态，再上传同一任务；网络重传只重传事件/结果，不重启 Harness。
8. Bridge 原子提交不可变终态与结果引用。Facade 读取后生成稳定 response id、created、model alias 和最终文本。
9. Sub2API 按既定业务合同处理已确认用量。客户端断线或回放不触发第二次执行，也不能触发第二笔结算。

## 6. 状态机与故障原则

以下是新文本任务的逻辑状态；实现时与 Bridge 现有状态建立一份明确映射，不重写图片任务的既有状态语义。

| 状态 | 含义 | 自动重新执行 |
| --- | --- | --- |
| ACCEPTED | 已持久接收，尚未发启动许可 | 不因重试创建新任务 |
| CLAIMED | 单一节点/槽已认领，尚未发启动许可 | 仅可在证明未授权启动且撤销旧 claim 后重领同任务 |
| START_GRANTED | 已持久发放启动许可，执行可能发生 | 禁止 |
| RUNNING | 已观察到原生执行 | 禁止 |
| WAITING_APPROVAL | 等待原生审批，仍占槽 | 禁止 |
| CANCEL_REQUESTED | 取消已请求但停止未确认，仍占槽 | 禁止 |
| RECONCILING | 执行状态不明，继续观察原任务，仍占槽 | 禁止 |
| SUCCEEDED | 原生成功 + 结果持久化一致 | 只回放 |
| FAILED | 已确认原生失败/适配失败，保留是否可能有副作用 | 不自动重跑 |
| CANCELLED | 已原子阻止启动，或原生执行已确认停止 | 不自动重跑；不等于撤销已有副作用 |
| EXPIRED | 仅用于未发启动许可的排队任务到期 | 不自动重跑 |

`execution_possible` 是单调布尔值：VPS 在返回首次 start grant 前将其设为 true，此后永远不能清零。租约过期和心跳超时不能改变这一事实。普通的 request_id、PID、线程 ID 均不能替代持久启动身份。

### 6.1 启动崩溃窗口

Node journal 先持久化 `launch_intent` 再 spawn，并使用互斥/CAS 防止两个本地进程同时消费许可。若恰在 intent 写入后、spawn 确认前崩溃，无法证明未执行就进入 RECONCILING，不盲目重启。此策略可能牺牲一次任务的可用性，但不许制造重复工具操作。

不能承诺任意外部工具的 exactly-once。可以验收的承诺是：同一已接收任务不因桥接层恢复而再次启动；事件和结果可至少一次上传、按身份去重；无法判定的窗口显式待处理。

### 6.2 取消、时限和终态竞争

排队时取消/到期与 start grant 竞争，必须在同一账本原子判定。取消赢则旧 claim 不得再启动；启动许可赢则走运行中取消。

HTTP 等待超时只结束等待，不把任务标为 FAILED/EXPIRED，也不释放运行槽。任务运行预算超时应请求原生取消，仍需确认停止后才能释放。仅杀掉 wrapper 父进程不证明所有原生工具子进程或异步副作用已经停止。

完成与取消竞态：已提交成功终态不可改写为取消；已确认取消后不得接受矛盾的成功回执。重复相同终态回执无害，矛盾回执进入人工调查且不重启任务。取消不回滚原生已写文件或已发送的操作。

## 7. 安全与用户隔离

每请求新 cwd/新 session 只解决上下文混用的一部分，不是安全沙箱。全权本地 Agent 可能读取同 OS 用户的其他目录、环境、浏览器、SSH 配置或原生凭据；不能靠 prompt 约定隔离。

可信 PoC 使用专用低权限 OS 环境和无敏感数据工作区，只接受操作者本人受信任务。公开多用户服务必须通过经验证的独立 OS 用户、容器/VM 或厂商支持的等效隔离方案；原生程序不支持该隔离方式，就保持内部测试，不降低门槛。

厂商凭证只供该原生运行环境使用。支持时阻止其工具子进程读取/导出凭据；不能有效隔离时不得让不可信租户执行能读取任意文件/环境的工具。不同租户不得共用可污染的全局记忆、MCP/插件配置、原生历史、缓存或桌面焦点。串行执行也不能消除这些问题。

首版不接收用户提供的本机绝对路径、可执行程序、环境变量、网络上传地址、任意附件 URL 或厂商 token。后续文件能力另做目录穿越、符号链接、大小、归属和下载鉴权合同，不借本次蓝图默认放开。

Facade 与 Bridge 不部署厂商 CLI/模型 SDK，不挂载本地认证目录，配置中不允许厂商推理 endpoint。生产 VPS 应有出站允许列表，仅访问自身任务服务/所需存储；软件包更新走受控运维流程，而非运行时自行下载执行器。

日志默认仅记录任务身份、状态、版本、时延、错误码；不记录 Authorization、Cookie、厂商凭据、完整 prompt、原始工具输出或私密推理块。原生面向用户的文本可以作为任务结果存储并按租户鉴权。

## 8. 有界资源与留存

单槽与任务容量在 Bridge 原子准入，不能靠 Facade 内存 semaphore。首版可以不排队，忙时在接收前返回 429；不要为了吞吐另建第二队列。队列是后续显式能力。

配置需覆盖请求体大小、等待时限、原生执行预算、事件/结果体积、磁盘配额、完成结果留存和幂等保留期。数值在 PoC 根据实际网络/客户端时限冻结，不冒充厂商限制。

幂等 tombstone 的保留期必须长于可重试窗口。结果正文已过期而身份记录尚在时，返回 RESULT_EXPIRED，不能同键生成新任务。未决任务及其启动证据不得自动清理。若存储损坏/恢复到旧快照，必须停新任务并人工协调未决执行，不能假装从未接收过。

版本升级保持所有未决任务的旧 profile/endpoint/账本可用；不把未决任务复制到新实例重跑。服务撤销/凭证轮换停止新任务时，还要保留受限的同任务收尾通道，防止无限孤儿执行。

## 9. 技术取舍

Facade 优先采用与现有 Bridge 相近的 Python HTTP 技术栈，少量类型化 DTO 与明确错误码；具体依赖版本在实施阶段固定。已有官方 SDK 需要其他语言时，仅在本地 Adapter 引入必要子进程，不要求重写 Bridge 或 Sub2API。

复用现有 Bridge 的持久账本、claim/start、结果提交和恢复，不并入 HAPI 形成双权威。API Wrapper 仅作为格式和接缝参考：在许可证未核定前不复制实现；薄外壳允许自行实现。不要继承 optional auth、全环境日志、全局 os.environ 改写、默认工具禁用、伪成功或估算 token 当精确用量。
