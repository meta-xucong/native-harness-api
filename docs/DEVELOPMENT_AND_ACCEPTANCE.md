# 分阶段开发与验收

基线：v0.1 / 2026-11-07。本文所有产品测试目前均为待执行清单；本次仅运行蓝图结构和抽象状态机检查。不能把下面的预期结果写成已经实测通过。

## 1. 实施顺序与最小交付

| 阶段 | 交付 | 退出条件 | 不授权的事项 |
| --- | --- | --- | --- |
| P0 蓝图 | 约束、接口、复用来源、审计与测试清单 | 文档审计无未处置阻断，检查脚本通过 | 不开发业务服务、不调用模型 |
| P1 离线合同 | Facade 薄外壳 + FakeHarness + Bridge 文本合同 + Sub2API mock 接缝 | 用户 Key 到假节点完整闭环；启动/恢复/错误模拟通过 | 不启用真实 Harness/生产用户/收费 |
| P2 单槽真实原生执行 | 获准的一种本地官方 Harness Adapter | Windows 实机原生输入、工具、审批、结果、取消、重启恢复可证实 | 不代替其他 Harness 验收；不开放不可信用户 |
| P3 Sub2API 真实闭环 | 一个不计费测试用户、一个渠道、非流式 | 经 Sub2API 返回真实原生文本；所有禁止重执行反例通过 | 不顺带修改全局渠道策略、钱包或部署生产 |
| P4 可选实时输出 | 原生事件到 SSE | 真增量、断线、背压、完整性、usage 口径验证 | 不对无原生增量的 Adapter 伪造流式 |
| P5 对外用户开放 | 安全隔离、授权、结算恢复、运营配置 | 所有生产门禁通过且用户明确批准 | 不把单槽可信 PoC 宣称安全多租户 |

第一版开发以 P1–P3 为范围；P4/P5 是明确后续，不能为了它们先开发复杂多节点调度。多执行槽可在隔离验收后增加，每槽独立运行环境，仍共用唯一 Bridge 任务权威。

## 2. 建议后续代码边界（尚不存在）

```text
native-harness-api/
  facade/              标准 API、Bridge HTTP 客户端、结果转换
  adapters/            本地官方 Harness 适配；不部署到 VPS
  contracts/           harness.text.v1 与 capability 定义
  tests/               FakeHarness、协议与故障注入
  docs/                本次开发蓝图
```

这是后续建议目录，不表示这些程序已经提交。Bridge 原仓库只补通用合同/持久化接缝；Sub2API 原仓库只补本渠道的身份、重试隔离和结算语义。原有仓库回归必须维持，不引入全局默认行为改变。

## 3. 可复用逻辑的开发核对

先核对 Bridge 当前 claim/start/commit 及 state store 的实际代码，再决定最小文本扩展；不要从文档猜接口字段。固定版本、记录修改前后差异，不复制现有生产数据库。

Adapter 每项能力以实际测试映射，不把“支持 start”推断为“支持无副作用恢复”，不把“支持 stream”推断为“每个事件都是用户可见正文”。prepare/readiness 必须不触发付费模型调用。

Sub2API 首先使用 Mock Facade 捕获实际 outbound URL/headers/body，证明鉴权上下文和幂等键正确、模型映射没有进入 Responses、失败分支不会换账号。当前特殊渠道开关的具体实现位置由代码审计确认，不凭蓝图自行编造管理配置。

## 4. 必测场景矩阵

以下均为产品实现验收，状态统一为 NOT_RUN。`audit/check-blueprint.mjs` 中同名概念模拟不是这些测试的替代品。

| ID | 场景 | 预期 |
| --- | --- | --- |
| T01 | 缺失/错误用户 Key 与服务 Key | 在相应边界拒绝，Node 启动数 0 |
| T02 | 客户端伪造租户/主体/内部 request 头 | Sub2API 剥离重建；不能串租户 |
| T03 | 同租户同键并发 POST | 一个 task、最多一次实际原生启动 |
| T04 | 同键但正文变化 | 409，保留原 task，不执行新内容 |
| T05 | 不同租户/主体同键 | 结果完全隔离；不可互查 |
| T06 | Facade -> Bridge 创建响应丢失 | 同身份查询/回放，不新建 task |
| T07 | claim 后未 start 时失联 | 仅原子确认未发许可后可重领同任务；旧 claim 失效 |
| T08 | start grant 已落库但 ACK 丢失 | execution_possible 保持 true，无第二次启动 |
| T09 | launch_intent 后、spawn 确认前崩溃 | 无法判定则 RECONCILING，不盲目再 spawn |
| T10 | RUNNING 心跳/网络中断 | 占槽并恢复同 task，不跨渠道推理 |
| T11 | 结果已产出、上传/确认丢失 | 重传同结果，不重新调用 Harness |
| T12 | HTTP 超时与客户端断开 | 只停止等待；任务不误终止、不自动释放运行槽 |
| T13 | 排队取消与 start 竞争 | 原子裁决；取消赢后不能启动 |
| T14 | 运行中取消、父进程退出但子任务仍活跃 | 不虚报已取消，不释放槽；原生停止需确认 |
| T15 | 完成与取消、重复/矛盾终态 | 成功结果不可改写；重复幂等；矛盾回执被拒绝 |
| T16 | 旧 node/旧 grant/旧 epoch 上传 | 不能覆盖新身份或别的任务 |
| T17 | False/字符串 0/空结果/缺原生终态 | 不当成成功，不能补通用回答 |
| T18 | 原生合法拒答 | 如实交付，不重跑、不替换答案 |
| T19 | 真实原生工具执行/需要审批 | 工具不被 wrapper 默认禁用；不自动全面批准；等待状态明确 |
| T20 | 新请求时本地离线且 VPS 无厂商凭证 | 503，厂商请求数 0；绝不云端 fallback |
| T21 | 已完成任务在本地离线时回放 | 返回原存储结果，原生启动数不增加 |
| T22 | 别名/profile 变更后同键回放 | 仍是原冻结版本结果，不偷偷换模型 |
| T23 | 同节点不同 Harness 别名并发 | 首版总运行槽仍为 1，不是每别名 1 |
| T24 | 429/502/504/截断/拒答触发 Sub2API 原有重试分支 | Harness 渠道无第二次新任务；其他渠道回归原样通过 |
| T25 | SDK 默认重试且用户不传幂等键 | 记录不保证跨请求去重；接入文档和示例配置阻止误用 |
| T26 | 调试/错误日志/结果中的秘密 | 无 Authorization、Cookie、厂商 token、原生敏感目录转储 |
| T27 | 跨工作区、全局记忆、MCP、缓存、原生历史读取 | 对外隔离环境拒绝；只分 cwd 不算通过 |
| T28 | 未知 usage、多个子调用、累计 usage 事件 | 不伪造 0/估算精确值，不漏计或重复求和 |
| T29 | 结果多次回放/客户端超时后完成 | 至多一次业务结算；未完成此项保持不收费 |
| T30 | 结果过期/账本重启/备份恢复 | 同键不重执行；未决证据保留，旧快照恢复先停准入 |
| T31 | 真实 SSE、错误流、缓冲/磁盘满 | 只转真实增量，失败不发成功 DONE，不能静默丢内容 |
| T32 | 跨升级、停新任务、Key 轮换 | 未决任务保留旧归属与收尾能力，不迁移重跑 |
| T33 | Sub2API URL/头/请求体捕获 | 路径仅到 Facade CC；内部身份真实，参数不被旧默认覆盖 |
| T34 | `/v1/models`、不支持参数、未启用 Harness | 鉴权且只列已启用能力；不支持请求在新任务接收前拒绝 |
| T35 | 节点不能上传某来源/其他租户任务 | Node Key 与 claim/grant 共同约束归属 |
| T36 | 原生凭据对工具读取和导出测试 | 不可信用户不能读取/外传；不满足则禁止公开工具执行 |

每条真实结果至少保留：Git commit、软件/Adapter 版本、OS、脱敏配置、request/task/grant 身份、时间线、Node 启动计数、终态与输出摘要。只记录成功截图或 API 200 不够；不要求模型自行生成哈希/字节偏移等额外证据。

## 6. 最终验收演示

使用 Sub2API 测试用户 Key 实际提交两次同幂等键请求；原生程序只执行一次，回答来自它。断开 PC 后，同键可以回放；换一个新键必须明确不可用，VPS 不得继续获得新模型回答。

制造一次原生执行期间的 HTTP 超时，再以原键恢复；结果最终可取，操作没有重复。展示一次原生工具和审批任务，说明原生能力没有被外壳抹掉。以两名隔离测试主体交叉请求，证明互不可读。

关闭服务或恢复失败时必须保留任务事实，不能靠删除数据库“恢复正常”。完成上述验收以后，仍需按本阶段是否开放用户/收费核对 G02/G06/G07。

## 7. 给后续开发者的启动指令

先读 README、AGENTS 和全部 docs，报告三仓库实际 HEAD 与本蓝图快照差异。仅实现 P1 的最小合同与 FakeHarness 闭环，单节点单槽，不修改任何正常渠道行为。完成自审、故障模拟和原仓库回归后提交独立 PR，列明已测/未测，不合并、不部署、不调用真实厂商。进入 P2 真实账号调用前取得明确授权，并从一种已确认可用的官方入口开始。
